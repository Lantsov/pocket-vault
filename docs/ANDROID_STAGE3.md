# PocketVault Android — этап 3/4: мобильный интерфейс

Работа выполнена в `feature/android-mvp`. Этап заменяет технический экран
минималистичным Android-интерфейсом; Core, формат `.pvlt` v1 и сервис файловых
операций этапа 2 сохранены. Публикация, подпись для распространения и этап 4
не входят в эту работу.

## Интерфейс

Палитра следует Windows-референсам
[главного экрана](images/pocketvault-main.png),
[расшифровки](images/pocketvault-decrypt.png),
[обработки](images/pocketvault-processing.png) и
[social preview](images/social-preview.png): фон `#141414`, карточки `#1E1E1E`,
границы `#353535`, основной текст `#F5F5F5`, вторичный `#A0A0A0`.
Основное действие — светлая кнопка `#F4F4F4` с текстом `#151515`.
Скругления 12 dp, отступы на сетке 8 dp, оригинальные векторные иконки.
Используется системный шрифт Android и системный `monospace` для названия
PocketVault и коротких технических подписей; внешних шрифтов нет.

Композиция адаптирована для телефона: логотип и настройки в шапке, слоган
«Your files. Your password. Your control.», карточка с кнопкой «Обзор файлов»,
пароль, одно основное действие, статус и подпись
«Offline · AES-256-GCM · .pvlt». Карточка выбранного документа показывает
реальное имя, доступный размер и кнопку очистки. Когда провайдер не сообщил
размер, это явно указано; путь из content URI не выдумывается.

Расширение `.pvlt` без учёта регистра автоматически переключает действие
на «Расшифровать» и скрывает подтверждение пароля. Исходное имя внутри
контейнера не показывается до успешной аутентификации. Системное сохранение
открывается после обработки. Для шифрования пароль нужно повторить;
оба поля поддерживают показ и скрытие. При пустом пароле, несовпадении
или отсутствии файла действие недоступно. Enter переводит фокус
на подтверждение либо запускает допустимую операцию.

Статус встроен в страницу: выбор и сохранение можно отменить, ошибки чтения,
сохранения, лимита и неверного пароля возвращают рабочее состояние.
Сообщение об ошибке аутентификации — «Неверный пароль или файл повреждён».
Во время обработки показан настоящий неопределённый `ActivityIndicator`;
процентов, паузы и кнопки отмены незавершённой криптографии нет.
После успеха показано подтверждение сохранения, исходный документ сохраняется.

Кнопки имеют состояния нажатия и недоступности. Появление карточки длится
180 мс и учитывает системное отключение анимаций. После успешного сохранения
используется необязательный лёгкий haptic, если устройство его поддерживает.
Он вызывает `View.PerformHapticFeedback` с `Confirm` на API 30+ либо
`ContextClick` на API 29, не требует разрешения `VIBRATE` и не меняет
результат сохранения при недоступности обратной связи.
Постоянных уведомлений и навязчивых модальных окон нет.

Настройки открываются обычной навигацией и содержат реальную версию приложения,
`.pvlt` v1, лимит 32 МиБ, ссылку на GitHub в системном браузере, полный локальный
текст MIT, отказ от гарантий и сведения об отсутствии аккаунтов, облака,
истории и восстановления пароля. Лицензия разворачивается на том же экране.

## Адаптивность и приватность

Страницы прокручиваются, ширина формы ограничена 560 dp на больших экранах.
Android system safe areas учитываются средствами MAUI. `AdjustResize` и
прокрутка позволяют работать с клавиатурой; поля используют системный размер
текста. PocketVault принудительно остаётся тёмным при светлой и тёмной
системной теме. Реальные проверенные размеры перечислены ниже отдельно
от свойств реализации.

`FLAG_SECURE` включён по умолчанию, включая Debug: содержимое окна защищено
от обычного системного снимка и отображения в списке недавних приложений.
У Debug есть явный параметр запуска `demo_screenshots`, позволяющий получить
демонстрационные снимки с публичными синтетическими данными. В Release
обработка этого параметра не компилируется. Это ограничение окна приложения;
внешний системный DocumentsUI или браузер принадлежат Android.

Пароли очищаются перед файловой операцией, при выборе/очистке файла, уходе
со страницы, сохранении состояния и уничтожении Activity. После очистки поля
снова маскированы. Native Entry отключает сохранение состояния Android и
autofill; пароли не восстанавливаются после пересоздания Activity и не пишутся
в Preferences. Управляемые строки нельзя гарантированно стереть из памяти.

Adaptive icon использует отдельный тёмный фон и векторный foreground замка,
производный от существующего логотипа PocketVault. MAUI формирует adaptive,
round и fallback-ресурсы; сторонних изображений нет. Splash также тёмный.

## Воспроизведение проверок

Команды выполняются из корня репозитория в PowerShell. Общие требования SDK,
сборка и устройство описаны в [ANDROID.md](ANDROID.md).

```powershell
./scripts/build.ps1
./scripts/build-android.ps1 `
  -AndroidSdkDirectory "$env:LOCALAPPDATA\Android\Sdk" `
  -JavaSdkDirectory 'C:\path\to\jdk-21'
./scripts/test-android-crypto.ps1 -Serial emulator-5554
./scripts/test-android-documents.ps1 -Serial emulator-5554
```

Windows-скрипт запускает 74 проверки: 43 Core/Windows/WPF и 31 синтетическую
проверку общего сервиса Android. Crypto smoke на Android проверяет 11 пунктов, включая оба legacy
fixtures; документный smoke проверяет 31 сценарий сервиса с синтетическим
`IDocumentAccess`. Скрипты проверяют свежий runId и Android runtime и сохраняют
JSON в `dist/android`. Эти проверки дополняют реальные системные диалоги,
но не заменяют их. Межплатформенный корпус и побайтовая проверка описаны
в [проверках этапа 2](ANDROID.md#воспроизводимые-проверки-этапа-2).

Для демонстрационных снимков Debug с синтетическим корпусом:

```powershell
$adbPath = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
$deviceSerial = 'emulator-5554'
& $adbPath -s $deviceSerial shell am force-stop com.lantsov.pocketvault
& $adbPath -s $deviceSerial shell am start -W `
  -n com.lantsov.pocketvault/.MainActivity --ez demo_screenshots true
# После подготовки нужного состояния на экране:
& $adbPath -s $deviceSerial shell screencap -p /sdcard/pocketvault-stage3.png
& $adbPath -s $deviceSerial pull /sdcard/pocketvault-stage3.png ./dist/android/pocketvault-stage3.png
```

Возврат обычной защиты: остановить приложение и запустить без этого параметра.
Снимки относятся к настоящему Android runtime; нейросетевые макеты для
подтверждения работоспособности не используются.

Для фиксации параметров экрана и проверки масштабирования:

```powershell
& $adbPath -s $deviceSerial shell wm size
& $adbPath -s $deviceSerial shell wm density
& $adbPath -s $deviceSerial shell settings get system font_scale
```

При проверке нужно пройти пустой экран, выбранный обычный файл и `.pvlt`,
пустой и несовпадающий пароль, показ/скрытие, обработку, успех, неверный пароль,
отмену выбора/сохранения и повторный запуск. На компактном экране,
в landscape и с увеличенным текстом проверить прокрутку, клавиатуру и
доступность основного действия. В обеих системных темах проверить тёмную
палитру, системные insets и навигацию настроек. Отдельно проверить обычный
запуск с `FLAG_SECURE`, очистку паролей и пересоздание Activity.

status bar y=0…47 не содержит текста приложения; прокручиваемый контент
обрезается с y=48. Изменённые системные настройки после проверки восстановлены.

## Сохранившиеся ограничения

Физическое Android-устройство, минимальный API 29 и ARM64 runtime отдельно
не проверены; ощущение haptic на физическом устройстве не оценивалось.
Синтетические сбои `IDocumentAccess` не доказывают поведение
каждого стороннего DocumentsProvider. Пиковая память для несжимаемого файла
32 МиБ на слабом физическом устройстве не измерена: операции Core остаются
в памяти. Сторонний провайдер может оставить частичный файл при отказе
в удалении; сохранена обработка и сообщение этапа 2. Прерывание криптографии
не реализовано. Гарантия стирания всех копий строк пароля не заявляется.

Этап 4, Google Play и Android-релиз не выполнялись.
